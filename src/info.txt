================================================================================
 1. PROJECT OVERVIEW
================================================================================

This project extends the MAP (Model- and Acceleration-based Pursuit) controller
with a deep neural network (NN) lateral steering controller.

The NN is trained using leave-one-map-out cross-validation across 5 racetracks:
  Overtake | Porto | Hangar | Berlin | F Map

For each holdout map, the model is trained on the other 4 maps (both speed
profiles: 0.6 and 0.825) and evaluated on the unseen map. This proves the model
generalizes to tracks it has never seen.

  - MAP Controller    → physics-based baseline (L1 guidance + Pacejka LUT)
  - ML Controller     → deep neural network (PyTorch MLP, 5 features → steering)
  - ML Controller 2   → classical ML (scikit-learn: XGBoost, RF, SVM, GP)

5 Physics-Informed Features (map-agnostic):
  d_m           — signed lateral deviation from racing line (m)
  heading_error — yaw error relative to racing line tangent (rad)
  kappa         — local curvature at nearest waypoint (1/m)
  vx            — longitudinal velocity (m/s)
  kappa_la      — lookahead curvature 10 waypoints ahead (1/m)

 3. HOW TO RUN CONTROLLERS
================================================================================

  MAP Controller (physics baseline):
    roslaunch map_controller sim_MAP.launch map_name:=<map>

  ML Controller — Neural Network:
    roslaunch map_controller sim_ML_controller.launch map_name:=<map>
    → node   : map_controller/src/ML_controller.py
    → model  : ML_controller/models_path/model_method2V2_holdout_<map>.pth
    → scaler : ML_controller/scaler_holdout_<map>.save
    NOTE: use the holdout model for whichever map you are testing on.
          The default launch file loads the overtake holdout (trained without
          overtake data) and runs on overtake_map.

  ML Controller 2 — Classical ML:
    roslaunch map_controller sim_ML_2_controller.launch map_name:=<map>
    → node  : map_controller/src/ML_controller_2.py
    → model : ML_controller/models_path/model_xgboost.pth  (currently active)

  Pure Pursuit (comparison):
    roslaunch map_controller sim_PP.launch

  Available maps : berlin | f | hangar | overtake_map | porto
  Default map    : overtake_map  (in all launch files)

 5. DATA PIPELINE
================================================================================

  Step 1 — Record MAP controller bag files (Section 4)
           One bag per map per speed:  run_<map>_0.6.bag  +  run_<map>_0.825.bag

  Step 2 — Run the full data pipeline (extract + clean + build splits):
    cd ~/f110_ws/src/Data/execution_files
    python3 extract_data_method2.py

    This script does everything in one shot:
      • Reads MAP bags (0.6 and 0.825) for each map
      • Extracts the 5 physics-informed features + steering label
      • Applies the 8-step cleaning pipeline (removes NaNs, outliers,
        saturation artifacts, low-speed data, duplicates)
      • Saves one leave-one-map-out training CSV per holdout map

    To rebuild a single holdout split only:
      python3 extract_data_method2.py --map porto

  Step 3 — Train the model (see Section 7)

  Step 4 — Record NN controller bags (Section 4) — for trajectory figure only

  Step 5 — Generate figures (see Section 8)

  Activation : ReLU  |  Dropout(0.1)  |  Adam optimizer  |  MSE loss

 12. KEY DESIGN DECISIONS
================================================================================

  - Physics-based features (d_m, Δψ, κ, v_x, κ_la) make the model map-agnostic.
    The same model works on maps it has never seen during training.

  - Leave-one-map-out cross-validation: each map is held out entirely from
    training (zero rows from that map in the training set). This is stricter
    than a random train/test split and proves genuine generalization.

  - Two speed profiles (0.6 and 0.825) per map in training gives the model
    exposure to different velocity regimes for better speed generalization.

  - Steering is clipped to ±0.4 rad on all ML controllers as a safety limit.

  - Speed is not predicted by the ML model — it uses waypoint velocity
    (wp_vx × velocity_scale). Only lateral steering is learned.

  - StandardScaler is fitted on training data only and saved alongside each
    model. The same scaler must be used at inference time.

  - ML_controller.py loads the holdout model matching the TEST map, not the
    training map. e.g. for overtake_map → holdout_overtake model.

 13. TRAJECTORY GENERATOR  (src/trajectory_generator/)
================================================================================

Generates the global racing line (global_wpnts.bag) used by all controllers.
Scripts are numbered in execution order.

── Files ─────────────────────────────────────────────────────────────────────
  01_extract_path.py    → extracts x,y path from a recorded lap bag
  02_optimizer.py       → smooths the path (Savitzky-Golay filter)
  03_geometry.py        → fits a closed B-spline through the path
  04_curvature.py       → computes curvature κ from spline derivatives
  05_velocity.py        → assigns physics-based speed at each waypoint
  06_bag_writer.py      → saves final trajectory as global_wpnts.bag
  07_generate_traj.py   → main entry point: calls 02 → 03 → 04 → 05 → 06

── Step-by-step ──────────────────────────────────────────────────────────────

  STEP 0 — Drive the car and record a lap:
    Terminal 1: roslaunch map_controller sim_MAP.launch map_name:=overtake_map
    Terminal 2: cd src/trajectory_generator
                rosbag record -O overtake_map_lap_record.bag /car_state/odom
    Press Ctrl+C after one full lap.

  STEP 1 — Extract x,y centerline:
    python3 01_extract_path.py
    Output: overtake_map_centerline_xy.csv

  STEP 2 — Generate full trajectory:
    python3 07_generate_traj.py
    Output: global_wpnts.bag

  STEP 3 — Copy to map folder:
    cp global_wpnts.bag src/F110_ROS_Simulator/maps/overtake_map/
