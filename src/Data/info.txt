================================================================================
 1. PROJECT OVERVIEW
================================================================================

This project extends the MAP (Model- and Acceleration-based Pursuit) controller
with ML-based steering controllers. Three controller types are available:

  - MAP Controller       → physics-based (baseline)
  - ML Controller        → deep neural network (PyTorch MLP)
  - ML Controller 2      → classical ML (scikit-learn)

Data was collected from real car runs on 5 maps at 2 speed profiles each.
Models were trained on 4 maps and tested on the 5th (porto) for generalization.


================================================================================
 2. HOW TO RUN
================================================================================

  MAP Controller (baseline):
    roslaunch map_controller sim_MAP.launch map_name:=<map>

  ML Controller — Neural Network (PyTorch MLP):
    roslaunch map_controller sim_ML_controller.launch
    → runs: map_controller/src/ML_controller.py
    → model: ML_controller/models_path/ml_model_relu_best.pth

  ML Controller 2 — Classical ML:
    roslaunch map_controller sim_ML_2_controller.launch
    → runs: map_controller/src/ML_controller_2.py
    → model: ML_controller/models_path/model_xgboost.pth  (currently active)

  Pure Pursuit Controller (comparison):
    roslaunch map_controller sim_PP.launch
  Available maps: berlin | f | hangar | overtake_map | porto
  Default map in all launch files: overtake_map

  To change the map, pass map_name argument:
    roslaunch map_controller sim_MAP.launch map_name:=porto

 6. MODELS  (src/ML_controller/models/)
================================================================================

All Method 2+ models use 5 input features:
  [d_m, heading_error, kappa, vx, kappa_lookahead]
  → 1 output: steering angle (radians)

Training split: 80% train / 20% test
Scaler: StandardScaler (saved to ML_controller/scaler_generalized.save)

----------------------------------------------------------------------
METHOD 1 — model_method1.py
----------------------------------------------------------------------
  Architecture : MLP  →  3 inputs (x, y, yaw)  →  64  →  64  →  2 outputs (steering, speed)
  Dataset      : method1_training_data.csv  (24,209 rows)
  Trained model: models_path/method1_model1.pth
                 models_path/method1_model2.pth
  Notes        : Early approach. Raw pose as input — not map-agnostic.
                 Predicts both steering and speed simultaneously.

  Notes        : First version with physics-based features. Trained on
                 only one map. Not generalized.

================================================================================
 9. KEY DESIGN DECISIONS
================================================================================

  - Physics-based features (d_m, heading_error, kappa, vx, kappa_la) make
    the model map-agnostic — same model works on unseen maps.

  - Porto map used exclusively as test map — zero data from porto in training.

  - Two speed profiles (0.6 and 0.825) used in training for speed generalization.

  - Steering clipped to ±0.4 rad as safety limit on all ML controllers.

  - Speed command = wp_vx * velocity_scale (from waypoint, not predicted by ML).

  - StandardScaler fitted on training data and saved — same scaler used at
    inference time in the ROS controller.


================================================================================
 10. TRAJECTORY GENERATOR  (src/trajectory_generator/)
================================================================================

Generates the global racing line (global_wpnts.bag) used by all controllers.
Files are numbered in execution order.

--- Files ---
  01_extract_path.py    → extracts x,y path from a recorded lap bag
  02_optimizer.py       → smooths the path (Savitzky-Golay filter)
  03_geometry.py        → fits a closed B-spline through the path
  04_curvature.py       → computes curvature κ from spline derivatives
  05_velocity.py        → assigns physics-based speed at each waypoint
  06_bag_writer.py      → saves final trajectory as global_wpnts.bag
  07_generate_traj.py   → main script: calls 02 → 03 → 04 → 05 → 06

--- Data files ---
  overtake_map_lap_record.bag     input  — raw lap recording (rosbag)
  overtake_map_centerline_xy.csv  intermediate — x,y path extracted from bag
  global_wpnts.bag                output — final trajectory for the controller

--- Test maps ---
  test | test_2 | test_map are clones of overtake_map used to test the results
  of trajectory generation. Copy global_wpnts.bag into each of these map folders
  to verify the generated trajectory before using it on the real overtake_map.

--- Step-by-step ---

  STEP 0 — Drive the car and record the lap:
    Terminal 1: roslaunch map_controller sim_MAP.launch map_name:=overtake_map
    Terminal 2: cd src/trajectory_generator
                rosbag record -O overtake_map_lap_record.bag /car_state/odom
    Press Ctrl+C after one full lap.

  STEP 1 — Extract x,y centerline from the bag:
    python3 01_extract_path.py
    Output: overtake_map_centerline_xy.csv

  STEP 2 — Generate the full trajectory bag:
    python3 07_generate_traj.py
    Output: global_wpnts.bag
    (internally runs: smooth → spline → curvature → velocity → save bag)

  STEP 3 — Copy bag to the map folder:
    cp global_wpnts.bag src/F110_ROS_Simulator/maps/overtake_map/
